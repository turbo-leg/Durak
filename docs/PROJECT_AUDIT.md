# Durak project audit

Owner: Durak Project Manager. Inspected 2026-10-20 at commit `9b23e50`.
This records the **unmodified baseline**; implementation results appear in PROJECT_PLAN.md.

This is an npm workspace monorepo, not a Three.js application yet.

## Custom rules to preserve

Read `GAME_RULES.md` and `GAME_NOTATION.md` before rule work. Verified in the engine/room/tests: 42 cards; ranks 7–K then 3, 2, A; black/red Jokers 17/18; Joker trump mapping; five/seven-card targets; clockwise Hot Potato chaining; 3/5/7 mass conditions and pair counting; one-to-one defense assignment; table pickup; refill to target; picked-up swap-card provenance; deck-empty escape. Teams and Horse also exist and must survive presentation changes.

Ambiguities remain explicit: Suhuh implementation versus prose, mass eligibility of low-hand defenders, prototype setup differences, and the meaning of the opening single-player/no-fixed-hand-size wording. No rule changes are authorized by stale standard-Durak assumptions.

## Follow-up findings during implementation

The baseline above remains historical. Implemented fixes and current validation are in PROJECT_PLAN.md.

- Full-match simulations exposed voluntary-pickup cycles in hard-bot decisions and a last-defender turn pointing at a player who had already escaped. Fixed the decision policy and clockwise skip; shared engine rules were retained.
- Browser validation exposed a leading attacker frozen at zero seconds, a duplicate Enter-key selection handler, and invitation input that uppercased/truncated case-sensitive room IDs. These have been addressed; tests and browser checks are recorded in the plan.
- Rematch/refresh validation exposed a cleared reconnect token never restored for the next match. Active seated-player state now persists it again; a real browser rematch followed by refresh recovered the game with one canvas.
- Dependency review found critical/high advisories that were not part of the initial test/build audit. Compatible updates removed all four critical findings. Remaining advisories and migration limits are documented in [security/DEPENDENCY_REVIEW.md](security/DEPENDENCY_REVIEW.md).
